# GovHealth Interop — Riscos

| Risco | Probabilidade | Impacto | Mitigação |
|---|---:|---:|---|
| Problema não ser grande | Média | Alto | medir antes/depois |
| “E-Saúde” não ser sistema único | Alta | Médio | mapear ecossistema |
| Integrações indisponíveis | Alta | Alto | adapters + pesquisa |
| Falta de API oficial | Média | Alto | priorizar mecanismos suportados |
| Automação quebrar | Média | Alto | evitar browser automation como base |
| Requisitos jurídicos crescerem | Alta | Alto | análise LGPD/contrato |
| Projeto virar sistema gigante | Alta | Alto | gates e MVP pequeno |
| Customização por órgão excessiva | Média | Alto | testar segundo ambiente cedo |
| Falta de caminho de contratação | Média | Alto | pesquisar modelo B2G desde o início |
| Segurança insuficiente | Média | Alto | threat model + baseline antes de produção |

## Principal risco de produto

Construir uma solução tecnicamente sofisticada para um problema que o usuário não considera suficientemente doloroso.

## Principal risco técnico

Tentar integrar diretamente múltiplos sistemas antes de compreender o fluxo real.

## Principal risco estratégico

Tratar substituição integral como objetivo inicial e aumentar o escopo antes da prova de valor.
